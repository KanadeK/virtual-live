# B站集成夹具

这些文件只实现本地 JSON Lines 测试桥接，不连接 B 站或真实 AI/TTS。正式服务默认 worker 不指向此目录。使用 `BILIBILI_WORKER` / `DOUYIN_WORKER` 指定对应文件，Node 路径通过各平台 `*_NODE` 指定。`BILI_FIXTURE_STATE_DIR` 可选，仅写进程 PID、平台和房间，便于核验停止及登录取消。

| 房间输入 | 场景 |
| --- | --- |
| 1001 | B站解析到字符串 `9007199254740993123` |
| 1101 | 一条新弹幕及同 ID 重复帧 |
| 1102 | 两人进场及重复帧 |
| 1103 | 同组礼物累计 1→3→结束3，含重复结束帧 |
| 1104 | 两分钟前的弹幕、进场、礼物，仅记录 |
| 1201～1205 | 需要登录、鉴权失败、未开播、无权限、限流 |
| 1206 | 重连后成功 |
| 1301 | 连续历史弹幕，测试滚动、来源隔离与 XSS；不播报 |
| 1401 | 一秒后旧来源弹幕，切源应先终止 worker |
| 1402 | 立即发送一份礼物，合并完成前切源应丢弃待感谢项 |
| 1501 | 登录助手保持等待，供取消与切源测试 |

其他输入只建立本地成功状态，不发送事件。`login.js` 是夹具，不会打开真实扫码窗口。除1501外返回固定虚构Cookie，验收报告不得把它当真实登录态。

`wire-worker.mjs` 供 `scripts/verify-bilibili-bridge.mjs` 使用：通过显式localhost传输注入读取本地HTTP/WS，但调用生产 `BilibiliApi`、`BilibiliSession`、解包与归一化模块，再按正式JSONL格式交给Java。它验证原始协议的连续链路，仍不是真实B站连接。生产worker的stdin不提供此注入入口。
